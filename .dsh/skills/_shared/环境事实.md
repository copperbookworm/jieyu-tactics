### 硬性坑（每个技能都适用）

1. **`--log-file` 必须给**。受限沙箱里 Godot 写不了 `user://` 会直接崩，且日志要写到工程内可写路径。
2. **数行必须用 LF 字节数**（`[System.IO.File]::ReadAllText($f) -split "`n"` 的 count-1）。
   `Get-Content` 在中文 UTF-8 文件上会**少数约 6%**，历史上把 Main.gd 数成 911 行。
3. **改完必须跑测试**，退出码 `0`=全绿 / `1`=有失败。上一轮的「全绿」不构成本轮依据。
4. **不要手动编辑 `.godot\`**（引擎缓存）。
5. **带格式的 docx 段落不要用 `paragraph.text = …` 覆盖**（会丢格式），用 `OxmlElement` 造同构 `<w:p>`。
6. 端口 **8000 / 9500 一次只能被一个 Godot 编辑器占用**；同时开两个项目，后开的连不上。
7. 「无 `class_name` 的模块」引用方**必须 preload 成常量**（裸写名字会解析失败）。
8. 写 PowerShell 时注意（**2026-10-02 实测的三个真坑**）：
   - **本机没有 `pwsh`**（PATH 里没有 PowerShell 7）。工具 shell 是 **Windows PowerShell 5.1**。
     调用脚本一律用 `& "<绝对路径>" -参数 值`，**不要写 `pwsh -File ...`**。
   - **`.ps1` 必须存成 UTF-8 带 BOM**。PS 5.1 读无 BOM 的 UTF-8 会按 ANSI(GBK) 解码，
     中文字符串会直接变成「字符串缺少终止符」这类**解析错误**。用 `write`/`edit` 工具改完要确认 BOM 还在。
   - **不要写 `Write-Host "..." -f $a, $b`**。PS 5.1 会把 `-f` 当成 `-ForegroundColor` 的缩写，
     报 `无法将值"31697500"转换为类型 System.ConsoleColor`。要写成 `Write-Host ("..." -f $a, $b)`。
9. Python 输出坑：本机 Python 的 stdout 默认走系统 ANSI 代码页（**GBK**），
   `print` 非 GBK 字符（如 `⚠`）会 **UnicodeEncodeError 崩溃**。
   技能脚本已统一 `sys.stdout.reconfigure(encoding="utf-8", errors="replace")`。
   另外 **pwsh 的 `>` 重定向会写成 UTF-16LE**（带 `FF FE` BOM），别用它抓中文日志；
   需要精确文本时让 Python 直接写 UTF-8 文件，或用 base64 中转。
10. `Get-ChildItem env:` 会因环境表有重名键而**抛异常**，别用它枚举环境变量。
