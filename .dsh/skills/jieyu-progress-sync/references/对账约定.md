### 「二、已完成」的版本段格式（照抄这个形状）
```
【第二十六版 · 候选 L5：T-M2 守住节点（防守阶段）——候选 L 收官（2026-10-01）】

· 未做（留给后续）：…
· 待办（下一轮）：① … ② …
```
- 段内小标题用 `·`，续行缩进两格（部分旧段用 Tab，各段自成一体，不要统一）。
- 测试项数**必须**写成「脚本数 / 总项数」，并给出与上一轮的差值（`quest_test 72 → 90`）。
- 「待办（下一轮）」是本文件被下一轮读取的关键字段，务必写。

### 锚点替换写法（照抄 `D:\Godot4.7_Proj\_progress_update.py` 的思路）
```python
import io, sys
PATH = r"D:\Godot4.7_Proj\jieyu-1\本项目开发进度.txt"
raw = io.open(PATH, encoding="utf-8", newline="").read()
EOL = "\r\n" if "\r\n" in raw else "\n"
lines = [l[:-1] if l.endswith("\r") else l for l in raw.split("\n")]

def idx_of(sub, start=0, end=None):
    end = len(lines) if end is None else end
    hits = [i for i in range(start, end) if sub in lines[i]]
    if len(hits) != 1:
        sys.exit("锚点 %r 命中 %d 次，预期 1 次" % (sub, len(hits)))   # 命中数不对 ⇒ 整体不写
    return hits[0]

# … 全部改动先在内存里做完，最后一次性 EOL.join(lines) 落盘 …
```
- **保留原 EOL**（本文件是 CRLF）。
- **保留 Tab 续行**语义（改「本次更新」抬头时，续行前导 Tab 不要丢）。
- 写完复核：行数只增不减（除非本轮明确删条目）、抬头日期已更新、「二、已完成」旧段逐字未动
  （可用 `git diff --stat` 看改动量是否只集中在预期几段）。

### 改 docx 的注意事项
- 先备份成 `解域游戏.docx.bak<NN>`：现有 `.bak`、`.bak55`~`.bak60`，取下一个**不存在**的编号。
- 用 `python-docx` + `OxmlElement` 造与文档同构的 `<w:p>`（带 `pPr`/`pStyle`），多行用一个 run 内多个 `<w:br/>`；
  参考既有脚本 `D:\Godot4.7_Proj\_docx_update.py`。
- **不要**用 `document.paragraphs[i].text = …` 这类只改文本的写法覆盖带格式的段落（会丢格式）。
- 改完必须复核：段落数 / 表格数**不低于**改前，一级标题仍在，`Document(path)` 能重新打开。
  `D:\Godot4.7_Proj\_docx_checks.json` 是上一轮的结构检查产物，可参考其口径。
- 自动 TOC 域不会因写入而更新，进度文件第六节已登记「需在 Word/WPS 按 F9」——照实保留该提醒。
