## 一、命名与目录硬规则

| 规则 | 说明 |
|---|---|
| 全小写 + 下划线 | `char_rifleman_base` ✅ ／ `角色-步枪兵` ❌ |
| **不许中文文件名** | 跨平台导出最容易在这里出事（门禁会红） |
| 帧序号补零两位 | `char_lower_walk_01.png` … `_08.png`，否则排序会错 |
| 同名不同用途要区分 | `_base` / `_hurt` / `_dead`，不要靠目录区分 |
| 文件名不带尺寸 | 改尺寸不用改名（尺寸写在规格里） |
| 目录 | 角色 `assets/chars/`｜载具 `assets/vehicles/`｜地图 `assets/maps/`｜UI `assets/ui/`｜特效 `assets/fx/`｜图标 `assets/icons/`｜单位 `assets/units/` |

## 四、怎么校验（每次入库前跑一次）

```powershell
$g = "E:\Godot_v4.7.1-stable_win64.exe\Godot_v4.7.1-stable_win64_console.exe"
& $g --headless --path "D:\Godot4.7_Proj\jieyu-1" --script res://tools/check_art_manifest.gd
# 要硬查「第一批 14 张必须全部到位」时：
& $g --headless --path "D:\Godot4.7_Proj\jieyu-1" --script res://tools/check_art_manifest.gd -- --require-batch1
```

- **退出码只反映「规格文件自己是否自洽」**：ID 唯一且 snake_case、路径都在 `res://assets/` 下、
  无中文文件名、尺寸要么正整数对要么显式 `null`、batch1 每一项都已给出尺寸。
- **素材到货数量只打印、不算失败** —— 资产是一张一张来的，「第 N 张还没来」不是工程坏了。
- 它同时是单元测试跑批里的**第 4 条门禁**（3 条几何 ＋ 1 条美术规格）。

## 五、入库注意

1. 纹理过滤是 **Nearest**（`default_texture_filter=0`）—— 像素风资产**不要**做抗锯齿/插值，否则糊。
2. **`.import` 文件要一起进版本库**（它是导入设置，不是缓存）。
3. 入库后**跑一次测试**：`--headless --script res://tools/run_tests_headless.gd`，确认没有脚本因资源路径变化而红。
4. **只有真的以 PNG 入库了**，才更新设计表的 `状态` 列 —— 「程序画的」≠「PNG 资产已完成」。

## 七、还是文档决策的两条（登记，不自作主张）

1. **给设计表加一列 `资源ID`** —— 现在第一列是「角色-步枪兵」这种人读描述，没法映射到 `res://` 路径。
   工程侧已经用 `art_manifest.json` 顶上了，但设计表的单一来源地位因此被动摇。
2. **设计表 `规格` 列有 16 条不可机器解析**（按需 6 / 按 8.2 几何 6 / 按 8.2 炮塔 2 / 半径 10m 1 / 椭圆 1），
   且有 1 组全角半角括号造成的近似重复。建议规格列只允许 `W×H`，其余移到备注列。
3. **角色：按兵种 4 张、还是共用 1 张染色（2026-10-07 第九十五版发现，需拍板）** ——
   `art_manifest.json` 按设计表列了 **4 张**兵种角色（步枪兵/精确射手/侦察兵/工程兵），
   但 docx **12.7.1 明确写「24 兵种共用动作」**，工程就是按这个做的：所有单位共用一套
   **Lower/Upper 分离**的角色图，**只用配色区分阵营**（`Enemy.gd` 里有原话）。
   ⚠ 单位模型上**根本没有兵种字段**（Ally / Enemy / Organization 都没有）⇒ 照 4 张画，
   工程最多只能用其中 1 张（再染色），**另外 3 张白画**。
   **两个选项**：(a) 统一 1 张共用图 + 阵营染色（＝现状，最省，美术只画 1 张）；
   (b) 给单位加兵种字段、4 张都生效（要先做兵种系统，属功能不是美术）。

## 八、入库之后：工程怎么把图用起来（2026-10-07 第九十四版）

### 之前的问题

`art_manifest.json` 是美术与工程之间的契约，但**工程侧原先一点都没读它** —— 准星、摇杆、标记全是
`_draw()` 现画的。结果是：**入库盘点全绿、画面上毫无变化**，美术把文件放进来了也没人用。

### 现在：`systems/art/ArtAssets.gd`（唯一取用入口）

```
ArtAssetsScript.has(id)        # 文件在不在
ArtAssetsScript.texture(id)    # 取纹理（懒加载 + 缓存）；不在返回 null
```

约定是「**文件在就用文件、不在就退回程序绘制**」：正式美术到位时**同名替换文件即可**，工程一行都不用改。
已经接上的三处：

| 位置 | 美术 id | 几何口径 |
|---|---|---|
| 摇杆底盘 | `ui_joystick_base` | 与程序绘制同半径，**位置/大小不变** |
| 摇杆球 | `ui_joystick_knob` | 半径 = 底盘 × 0.45（81/180 正好 0.45） |
| 战场标记 | `ui_mark_enemy` … `ui_mark_rally` | 与程序圆点**同半径**（`MARK_ICON_RADIUS`），只是形状变了 |

### 还没接的（有意留着）

- **准星 `ui_crosshair`**：程序那支是**三角箭头**，约定「箭尖＝纹理中心＝屏心，箭身向 -x」，
  旋转轴落在箭尖上。占位图画的是四向十字，**不满足这个约定** —— 直接换会改掉瞄准语义。
  要么美术按「箭尖居中」出图，要么先改工程里那条约定，别闷头换。
- **角色 4 张**（`char_*_base`）：队友/敌人现在是 `_draw()` 画的圆身 + 朝向楔，换成贴图要顺带处理
  **旋转与朝向**（俯视角色随朝向转），属于下一步活儿。
- **按钮九宫格 `ui_button_nineslice`**：要在 `UiKit` 里按 `StyleBoxTexture` 接，改动面比上面三处大。

### 一条纪律

`test/art_assets_test.gd` 会逐条比对 **ArtAssets.PATHS 与 art_manifest.json 的 path**。
两边都是手写的，只改一边就会出现「盘点绿、工程读另一个路径」。改路径时**两边一起改**，跑测试就知道有没有漏。
