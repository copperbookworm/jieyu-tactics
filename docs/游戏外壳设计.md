# 解域 · 游戏外壳设计（大厅 / 模式选择 / 设置 / 界面跳转）

> 依据：`squad-2d/解域游戏.docx` › 11.4 对局外界面、5.3 / 5.7 各模式胜负表、20 章 AI 参谋口径、22.6 PVEVP、22.10 第一版范围（2 阵营 / 1 地图 / 3 模式）、4.15 操作提示。
> 使用者 2026-10-03 拍板：① 大厅做启动入口；② 模式**真做多套规则**（不是换皮）；③ 设置五项全做；④ 局内要暂停菜单，并顺带重排 HUD 按钮。

## 一、玩家能做什么（发布说明）

装包启动 → **进大厅**（不再是直接进对局）。大厅上四个按钮：开始游戏 / 设置 / 玩法说明 / 关于。

**开始游戏** → 模式选择：左边列 11.4 的 6 个模式，右边是该模式的规则说明（时长、加时、AI 参谋开关、出处）。
第一版只有 3 个能选（22.10 拍板：PVP 竞技 / PVP 休闲 / PVEVP），另外 3 个**置灰并写明「后续版本」+ 理由**——
列出来是为了让玩家看得出「文档里有、这版没做」，不是按钮坏了。

选完按**开始对局** → 世界按该模式的规则建起来。局内右上角多了一个**暂停**键：
按下 → 世界冻结、HUD 收起、弹出暂停菜单（继续对局 / 设置 / 返回大厅）。
一局打完 → **结算屏**（胜负 / 结束原因 / 占领 / 战力分 / 主线任务）→ 再来一局 或 返回大厅。

**设置**从大厅和暂停菜单都能进，五项：音量、操作提示开关、AI 参谋竞技开关与入口、对局默认值、本地数据与关于。

## 三、屏幕与跳转

```
                                         [reset_to]
  启动 ──► 大厅(lobby) ──push──► 模式选择(modes) ──开始对局──► 对局(MatchHost + Main.tscn)
              │  │                     │                            │
              │  └─push─► 说明(info)     │                            ├─暂停键─► 暂停(pause)
              └──push──► 设置(settings) ◄─┘                            │            │
                    （从暂停进设置时，暂停留在栈底）                      │            └─push─► 设置(settings)
                                                                      └─胜负─► 结算(result)
```

| 规则 | 取值 | 工程落点 |
|---|---|---|
| 同一时刻只有一屏可见 | 路由 `_sync()` 逐屏设 `visible` | `ScreenRouter._sync` |
| 栈底不能退 | `can_pop()` = 栈深 > 1；返回按钮只在能退时出现 | `ScreenBase.refresh_navigation` |
| 重复 push 同一屏被忽略 | 防连点 | `ScreenRouter.push` |
| 返回键只有一个出口 | ESC / `ui_cancel` / Android 实体返回 | `ScreenRouter._unhandled_input` + `_notification(NOTIFICATION_WM_GO_BACK_REQUEST)` |
| 菜单在最上层 | layer 100（HUD 1、战术地图 10、AI 参谋面板 90） | `ScreenRouter.STACK_LAYER` |
| 暂停时菜单仍要响应 | 路由 `process_mode = ALWAYS` | `ScreenRouter._ready` |
| 进对局 / 回复对局要把菜单收干净 | `router.clear()` | `App.start_match` / `MatchHost.resume` |

**为什么要有路由，而不是各屏自己 show/hide**：跳转是**一处状态**，散在六个屏里必然出现「两屏同时可见」这种脏状态；
而且几何门禁只采集 `is_visible_in_tree()` 的控件——只要同一时刻只有一屏可见，各屏布局就能各自独立地被钉住。

## 四、模式规则：三个模式到底哪里不一样

第一版可选 3 个（22.10 原文），**每一个的差别都接了线**（不是文案差别）：

| | PVP 竞技 | PVP 休闲 | PVEVP |
|---|---|---|---|
| 胜负口径 | `occupy` 占领数 | `occupy` 占领数 | `objective` 战术目标 |
| 时长 | 15 分钟 | 15 分钟 | 20 分钟（22.6 候选 20~30 取 20） |
| 加时 / 平局 | 3 分钟突然死亡 → 仍平即平局 | 同左 | **无加时、无平局** |
| 重生预算耗尽 | 判负 | 判负 | 判负 |
| 友伤 | **开** | **关** | 关 |
| AI 参谋 | **关闭**（20 章：只有竞技 / 严格对抗才关） | 开放 | 开放 |
| 出处 | 5.3 / 5.7 | 5.3（「与竞技同表」） | 5.3 / 22.6 |

接线点（**每一处都能在代码里找到**）：

| 模式字段 | 接进哪里 | 证据 |
|---|---|---|
| `win_rule` / `duration_s` / `overtime_s` | `MatchHost._apply_mode_rules` → `MatchFlow.apply_mode()` | `systems/match/MatchFlow.gd`；战术目标完成走 `_on_objective_quest` |
| `competitive` | `App.start_match` → `AiAdvisor.competitive` | `ui/app/App.gd`；设置屏可手改，但**开局会被模式覆盖**（面板上写明） |
| `friendly_fire` | `Player.shoot` → `MatchRules.with_friendly_targets` | 开友伤时把 `friendly` 组并进射击目标（排除自己、不重复） |
| `available` / `locked_reason` | 模式选择屏置灰 + 写明理由 | `ui/screens/ModeSelectScreen.gd` |

**刻意没有做的字段**：每个模式的敌人数。docx 全篇没有「一局多少人」的口径（待拍板清单第 13 条），
凭空给每个模式编一个数字就是「文档没落地」。敌人数因此**只**由玩家设置（GameSettings.default_enemy_count）。
兵种 / 载具同理。

**默认模式 = PVP 休闲**：它是唯一「既有占领规则 + AI 参谋开放 + 关友伤」的组合，与今天工程的行为最接近，回归面最小。

## 五、设置项：存哪里、什么时候生效

落盘：`user://game_settings.cfg`（`GameSettings.save_to_disk()`）。**没有 autoload**——
本工程对 autoload 有硬约束（`--script` 模式下未注册，谁在编译期引用全局名谁就炸），
而这些值只需要「App 持有 + 界面读写 + 存盘」，RefCounted 实例够用，还顺带能在单测里换临时路径。

| 设置项 | 默认值 | 生效点 | 补齐的既有欠账 |
|---|---|---|---|
| 音量（0~1 滑条） | 1.0 | `App.apply_runtime` → `Audio.master_volume_db` | AudioSystem 头部自述「未做：…音量设置界面」 |
| 静音 | false | 同上（`Audio.enabled`） | 同上 |
| 操作提示开关 | `GameConfig.TIP_DEFAULT_ENABLED` | `HudBuilder.set_tips_enabled` | HudBuilder 注释「设置界面后置，先给 API」 |
| AI 参谋竞技开关 | 关 | `AiAdvisor.competitive` + `save_config` | 面板里原本只能自己改 |
| AI 参谋面板入口 | — | `AiAdvisorPanel.open_panel()`（本次新加的公开入口） | 原来只有局内那个入口按钮 |
| 对局默认：模式 / 兵种 / 载具 / 敌人数 / 地图种子 | 休闲 / 步枪兵 / ifv_a / 2 / 20260101 | `App.start_match` 的 options → Main 的 `@export` | 原来这些只能在编辑器里改 `@export` |
| 清空 AI 用量账本 | — | `AiAdvisor.clear_records()` | — |
| 清除 API key | — | `AiAdvisor.clear_api_key()` | — |
| 关于：版本 / 引擎 / 分辨率 | — | `App.VERSION` | 原来游戏里看不到版本号 |

**音量换算**（`GameSettings.volume_to_db`）：线性 0 算不出 dB（−inf），所以 0 与静音都取 `MUTE_DB = -60`。

## 六、暂停与结算

| 项 | 做法 | 为什么 |
|---|---|---|
| 暂停时世界冻结 | `get_tree().paused = true` | 引擎自己的暂停，不用逐个模块加开关 |
| 暂停时 **HUD 收起** | `HudBuilder.set_shell_visible(false)`（HUD 层 + 战术地图层） | HUD 的按钮平铺在同一层，暂停面板压上去会产生一堆「真实存在但没法修」的重叠；而且暂停时本来也不该点战斗键 |
| 世界仍在渲染 | Main 的 Node2D 不是 HUD 层的子节点 | 看起来是「冻结的战场 + 暂停菜单」 |
| 暂停键谁接线 | `HudBuilder` 只负责**建**，`MatchHost._wire_pause_button` 接线 | Main.gd 守着 398/400，加不了这一行；单独跑 Main.tscn 时它就是个没接线的按钮（集成冒烟钉住这一点） |
| 结算 | `EventBus.match_finished` → `MatchHost._on_match_finished` → `App.on_match_finished` → `router.reset_to("result")` | 走事件总线，三个模式共用一屏 |

## 七、边界条件与本次踩到的坑

1. **`_ready` 不在 `add_child` 里同步跑**：几何门禁脚本在 `_initialize` 里 `add_child` 之后立刻读
   `App.router` 拿到 null——引擎把 `_ready` 排到第一帧。门禁因此加了启动阶段（`BOOT_FRAMES`）。
2. **门禁会「空跑通过」**：App 起不来 ⇒ 一屏都没注册 ⇒ 零重叠零失败，看着像全绿。
   现在两处钉住：屏幕注册清单体检 + 「这一屏必须真的采集到可见控件」。
3. **GDScript 不允许子类遮蔽父类常量**：六个屏幕都写了 `const UiKit := preload(...)`，与 `ScreenBase` 的同名常量冲突
   （`The member "UiKit" already exists in parent class`）——子屏幕删掉，用继承来的。
4. **`Button` 的最小高度不是 `custom_minimum_size` 说了算**：它由 StyleBox 的上下内边距 + 一行字决定（实测 44）。
   模式选择屏 6 个按钮 × 44 把 `MarginContainer` 顶到 546 ⇒ 几何门禁报「出屏 6 px」。
   修法是 `UiKit.compact_button`（内边距 10 → 5，实测最小高度 ~36），不是把 `size.y` 改小（改了没用）。
5. **`--script` 模式下 `class_name` 不在全局类缓存里**：所有新模块一律不写 `class_name`，引用方 `preload`。
6. **`var x := 未标类型成员.属性` 编译不过**（`Cannot infer the type`）：`ctx` / `settings` / `match_host` 都是鸭子类型，
   访问它们的属性要显式标类型。
7. **autoload 一律运行时按路径取**：`App.advisor()` / `App._current_hud()` 用 `get_node_or_null("/root/...")`，
   不写全局名。
8. **设置路径可注入**（`App.settings_path_override`）：几何门禁指向一份不存在的临时路径，
   否则「界面文字随本机设置变」会让布局与基线在不同机器上不一样。

## 九、未做 / 待拍板（写在界面上，不假装）

**未做（列出来但置灰，理由写在模式卡上）**：PVP 装甲对抗、困难模式、兵棋模式（22.10 降级为后续版本）。

主题色选择、健康系统与防沉迷提示。

**待拍板**：
1. **「竞技 / 严格对抗」到底包含哪几个模式**：原文只写「只有竞技 / 严格对抗才关闭 AI 参谋」。
   当前实现＝**只有 PVP 竞技**关闭；休闲 / PVEVP 开放。困难模式（若以后做）与兵棋是否算严格对抗要定。
2. **AI 参谋公平性声明**：19 章 ㉝ 仍是开口项——要不要在模式说明或加载页写「本模式允许使用 AI 助理」。
3. **PVEVP 的「VP」那一半**：5.3 定「单人 PVE」，21.3.8 明说「玩家之间是否会间接对抗…无来源、待撰写」。
   当前实现的战术目标是「完成当前主线任务」（本版＝夺下第一个节点），这只是占位口径。
4. **阵营选择**：首版大厅放 4 选 1（11.4）还是 2 选 1（22.10）。
5. **人数口径**：所有 PVP 模式都没写「多少人一局」（5.5 只举例 32 人）。当前敌人数由玩家设置决定（1~8），
   没有「模式规定人数」。
6. **模式差异要不要再拉大**：当前三个模式的差别全在「规则层」（胜负口径 / 时长 / 友伤 / AI 参谋）。
   若还要「步兵对抗」「装甲对抗」这类**编成层**差异（有没有载具、坦克数量），需要在 ModeTable 上加字段并接线。

**与使用者选项的一处订正**：选项原文写的是「步兵对抗 / PVP 装甲对抗 / PVEVP」，
但 22.10 原文的第一版三个模式是「PVP 竞技 + PVP 休闲 + PVEVP」，且明确把装甲对抗 / 困难 / 兵棋降级为后续版本。
本实现按**文档**走（竞技 / 休闲 / PVEVP 三套真规则），把装甲对抗等标为置灰占位。
若使用者要的就是「步兵对抗」这类编成差异，见待拍板第 6 条。
