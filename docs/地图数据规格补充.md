# 《解域》地图数据规格补充（jieyu_map 插件引入的扩展字段）

> 本文只记录**超出 `解域游戏.docx` 12.8 已定稿内容**的部分，供「要不要把这些补进正式文档」拍板。
> 已定稿的字段一律照抄，没有改动：本文提到的一切实现在
> `addons/jieyu_map/core/JieyuMapSpec.gd` 里都有对应常量与出处注释。

---

## 一、目录结构：与 12.8.1 的差异

12.8.1 写的是 `Maps/<map_id>/`（引擎无关的抽象路径）。
本工程落在 **`res://assets/maps/<map_id>/`**，理由是工程现有的自制高度图约定（`GameConfig.MAP_HEIGHT_DIR`）就在这里，
且 `Main.map_height_image` 指向 `res://assets/maps/*.png`。

同时**额外产出**一份 `<map_id>_height.png`（单张扁平高度图，放在 `assets/maps/` 根下）——
这是为了让工具链产出的图**不改任何工程代码就能试跑**（直接把 `map_height_image` 指过去）。

## 二、新增：内容层（4.17 环境互动区的图上标注）

12.8.1 的六份文件里没有「环境互动区」这一项，而 4.17（泥泞 / 雪地 / 草丛）需要空间数据。
工程现状是 `MapGenerator.demo_terrain_zones()` 硬编码三片圆形区域。

**插件新增两张可选图**（在 `meta.json` 的 `content_layers` 字段里声明；没有这两张图时工程应静默跳过）：

| 文件 | 格式 | 语义 |
|---|---|---|
| `content.png` | RGB8，1000×1000 | **行序方案**：第 N 行 = 第 N 片区域；同一片区域内必须纯色。颜色→kind：`(107,82,51)` 泥泞 / `(240,245,255)` 雪地 / `(61,133,61)` 草丛 |
| `material.png` | L8，1000×1000 | **材质 id 图**：0 = 无，1 = 泥泞，2 = 雪地，3 = 草丛 |

`meta.json` 里的声明：

```json
"content_layers": {
  "name": "terrain_content",
  "rows_file": "content.png",
  "material_file": "material.png",
  "merge_mode": "max_conceal"
}
```

> `merge_mode` 的口径与 `systems/terrain/TerrainZones.gd` 一致：速度取**最慢**、隐蔽取**最强**并封顶
> `GameConfig.TERRAIN_CONCEAL_MAX`。两张图给的是同一份数据的两种表达，**任选一张**即可；
> 两者同时存在时以 `material.png` 为准。

**要拍板的点**：工程侧还没有读这两张图的代码。落地位置建议是
`WorldSetup._build_terrain_zones()` 换成一个「从 map 目录读内容层 → 生成 TerrainZone 节点列表」的函数
（`TerrainZones` 的纯查询层不用改）。

## 三、新增：`meta.json` 扩展字段
12.8.7 的 meta 字段全部保留，插件额外写了四个键（**工程侧不读也不影响运行**）：

| 字段 | 用途 |
|---|---|
| `content_layers` | 见第二节 |
| `content_counts` | `[泥泞格数, 雪地格数, 草丛格数]`，供人一眼看内容层规模 |
| `roads` | `[{name, path[[x,y]…], width_m}]`：12.8.1 没有单独的道路文件，插件把道路折线记在这里（道路的**地形效果**已经烘进高度图，这份记录只用于重生成与审阅） |
| `recipe` | 生成配方回执（seed / grid / node_count / 河谷参数 / generator），保证「这张图是怎么来的」可复现 |

## 三点五、「哪些东西能摧毁」在数据里怎么表达（文档现状与插件口径）

**文档现状（原样核对过 `解域游戏.docx` 全文）**：

- `occluders.json` 每项有 `destructible` 与 `hp`（标「可选」）⇒ **判据只有这一个布尔字段**；
- 有明文耐久的只有**沙袋**：4.17 / 20.5「轴对齐矩形沙袋（7.2 × 2.2 m、顶高 1.1 m、**耐久 200**）、
  只挡通视与子弹、不阻挡人员通行；可破坏 —— 耐久清零后退出 occluder 组」；
- 建筑只有**思路**（4.17「可破坏掩体（建筑）的毁伤沿用 8.2.6 的载具毁伤思路（部位 + 血量）」），
  没有血量、没有部位、没有破坏后的地形/通行变化；
- 文档**自己承认这个缺口**：21.2.2 ⑧「建筑毁伤规则：多处提『建筑毁伤更多』，
  但只有载具（8.2.6）与沙袋（20.5 工程侧）有血量，建筑本身没有毁伤判定」；
- 第一版范围（22.10）把**建筑毁伤**明确降级为「后续版本」。

**插件据此定的口径**（`JieyuMapGen` / `JieyuMapChecks`）：

| 物件 | 插件写什么 | 依据 |
|---|---|---|
| 建筑（building） | `destructible: true` + `hp`（按占地分档）+ 三段 `damage_profiles` | 2026-10-03 拍板①（见三点六） |
| 半高墙 / 沙袋（wall） | `destructible: true` + `hp: 200` + 三段 `damage_profiles` | 4.17 / 20.5 的沙袋耐久，与工程 `GameConfig.COVER_HP` 同值 |
| 地形（高程） | 不参与可摧毁性 | 12.2 补充：1 m 高程网格承担全部**静态**地形与固定掩体 |

校验器两条：`destructible=true` 却没有 `hp`（WARN）、三段阈值表缺行或比例越界（ERROR）。

## 三点六、2026-10-03 使用者拍板的四条（已落地）

| # | 拍板 | 落地位置 |
|---|---|---|
| ① | **遮挡体一律可摧毁**（`destructible = true`） | `JieyuMapSpec.DEFAULT_DESTRUCTIBLE`；`JieyuMapGen.place_settlements` / `JieyuMapPainter.add_occluder` 的默认值 |
| ② | **建筑结构值锚点「标准档 1200」**（与 FOB 同档）；伤害按**弹药类别**分档，普通子弹为 0 | `JieyuMapGen.building_hp_for_footprint()`；`data/weapons_data.txt` 的 `structure_damage` 列；`data/vehicles_data.txt` 的 `gun_structure_damage` / `atgm_structure_damage` 列 |
| ③ | **破坏后留贴地残痕 + 小减速，不影响通视** | `entities/zone/RubblePatch.gd`（与泥泞共用移速链路）；摧毁段的 `rubble` 声明 |
| ④ | **三段：完好 → 受损（`h_top` 变矮）→ 摧毁（退出遮挡）** | `occluders.json` 的 `damage_profiles`；`entities/cover/Cover.gd` 的 `is_damaged()` / `height_scale()` / `effective_height()` |

**② 的伤害分档（工程实测值，见 20 章数据表）**：

| 弹药类别 | 武器 | 对建筑伤害 | 拆一栋 1200 需要 |
|---|---|---|---|
| 手枪 / 冲锋枪 / 5.8·5.56·5.45 步枪弹 / 7.62 机枪 / 精确射手（共 20 把） | qbz191…pkm | **0** | 打不动 |
| 12 号霰弹 | remington870 | 25 | 48 发 |
| .50 反器材 | m107barrettm82 | 55 | 21.8 发 |
| 40mm 榴弹 | m320 | 90 | 13.3 发 |
| 单兵反坦克火箭 | at4rpg7 | 600 | **2 发** |
| 单兵反坦克导弹 | 12javelin | 800 | **1.5 发** |
| 12.7mm 车装机枪 | apc_apcb / apc_apcd / veh_18 | 30 / 30 / 20 | 40 / 40 / 60 发 |
| 25 / 30mm 机炮 | ifv_ifvb / ifv_ifvc / ifv_a / heli_* | 35 / 35 / 45 / 45–50 | 26.7–34.3 发 |
| 105mm 突击炮 | veh_mgsb | 60 | 20 发 |
| 120 / 125mm 主炮 | mbt_t1…t5 | 280 | **4.3 发** |
| 155mm 榴弹炮 | sph_spha…c | 420 | **2.9 发** |
| IFV 炮射导弹 | ifv_a 的 ATGM | 800 | **1.5 发** |

> 口径说明：`structure_damage` **缺列或空串 ⇒ 0（打不动）**，不是「能打」——
> 默认值必须落在「普通子弹打不动建筑」这一侧（`WeaponTable.DEFAULT_STRUCTURE_DAMAGE = 0`）。
> 一栋标准建筑要 4–5 发主炮或 2 发火箭，工程意义是**拆楼是重武器的活，不是步枪的活**。

**④ 的阈值表形态**（`occluders.json` 每条可摧毁物一行）：

```json
"damage_profiles": [
  { "state": "intact",    "damaged_below_ratio": 0.70, "height_scale": 1.00, "blocks_sight": true },
  { "state": "damaged",   "damaged_below_ratio": 0.00, "height_scale": 0.45, "blocks_sight": true },
  { "state": "destroyed", "damaged_below_ratio": -1.0, "height_scale": 0.00, "blocks_sight": false,
    "rubble": { "material_id": 4, "radius_scale": 1.25, "speed_scale": 0.70 } }
]
```

- 建筑的受损 `height_scale` 取 **0.60**（比沙袋的 0.45 保守：楼塌一半不该比沙袋还矮）。
- 受损档的物理含义只是「挡视线的缝变大」：通视与子弹都走 `top_height_at()`，
  沙袋顶高从 1.1 m 掉到 0.495 m ⇒ 越过它所需的视线高度整整降 0.605 m。
  **0.495 m 仍落在文档 4.6 的「矮掩体 0.5–2 m」档里**，所以卧姿仍越不过去 —— 受损不等于消失。
- 工程侧读法：`Cover.is_damaged()` / `height_scale()` / `effective_height()` 已把三段折进现有接口，
  `SightSystem` 与 `BallisticsSystem` **一行都不用改**（它们只问 `top_height_at()`）。
- 残痕用的 `material_id = 4` 是 `material.png` 的新增取值；工程侧
  `MapGenerator.terrain_zones_from_material_image()` 解析时**跳过 4**（残痕由摧毁时现落，不从图里读）。

**仍未做（登记为欠账）**：工程侧还没有「按 `structure_damage` 结算建筑伤害」的调用点。
建筑目前是 `Cover`（掩体）而不是可被炮击的目标实体 —— 复用 `Fob.gd` 的结构值结算即可，
但要先定「俯视 2D 下建筑的可命中体积」，这一条留给下一轮。

## 四、新增：12.8.8 待确认项的口径选择

12.8.8 第 ④ 条写着「Occluder 与 zones 的标注方式（编辑器插件 vs 手写 JSON）」——
**本轮选定：编辑器插件 + 无头 CLI 双入口**，理由：

- 手写 JSON 的致命问题是**没有校验**：核心区里塞建筑、进入通道只写 1 条、节点间距 80 m，
  这些在 JSON 里都是合法数据，但会让地图不可玩（4.2 / 六章）。
- 因此插件的重点不是「画得快」，而是**画的时候就告诉你哪条铁律破了**：
  `JieyuMapChecks` 把六章能机器判的指标全部落成断言，`validate` 有 ERROR 就退出码 1。
- agent 走 CLI（可脚本化、可批处理、退出码可判），人走 dock（所见即所得）。

12.8.8 第 ③ 条「导航网格方案」**仍未决**：因此校验器里
「侧翼绕后路径 ≤ 正面 ×1.5」只给 INFO 提示，不编造数字。

12.8.8 第 ⑤ 条「载具坡度通行阈值」当前取 `GameConfig.MAX_SLOPE_DEG`（30°，12.8.5 的候选值已落成常量）；
插件的道路画笔另有更严的 `CORRIDOR_FLAT_DEG`（8°）用于「这段路能跑车」的局部判据。

## 五、验证器采用的通视口径（与工程一致性声明）

校验器里的通视判定（`JieyuMapChecks._is_open_line`）与工程 `SightSystem` 保持同一条数学内核：

- 采样：1 m 网格 + 双线性插值；容差 `GameConfig.SIGHT_MARGIN`（0.3 m）
- 眼高：`GameConfig.SOLDIER_EYE_HEIGHT`（1.6 m）
- 判据：视线高度 < 地形高度 + 容差 ⇒ 被挡（与 `systems/terrain/SightSystem.gd` 的地形层一致）

**差异（有意为之）**：校验器不读 `Occluder` 场景节点，而是用自己的「有掩体采样格」（多边形 + 5 m 缓冲）。
理由是校验发生在**还没有实例化场景**的时候；代价是它比运行时的三级通视**更保守**（更容易判"挡"）。
如果将来要逐点复验，用 `Main` 的 `map_preview_mode` 走 `MapPreview` 探针即可。
