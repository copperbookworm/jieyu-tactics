1. `adb install` 之后**立刻** `ime enable` 会报 `Unknown input method ...` ——

   否则编码在到达手机前就已经错了。实测注入「中文注入成功」**字节级一致**（md5 `02bc4f78…`）。
4. 原默认输入法是 `com.google.android.inputmethod.latin/...LatinIME`；
   用完想还回去：`& $adb shell ime set com.google.android.inputmethod.latin/com.android.inputmethod.latin.LatinIME`。

#### ⚠ 用 ADBKeyboard 注入的前提（2026-10-03 实测踩到）

**`ADB_INPUT_TEXT` / `ADB_INPUT_B64` 只在 ADBKeyboard 是「当前输入法」时才有效**——
它的广播是靠 `AdbIME` 这个 IME 服务里注册的 receiver 收的，服务没起来广播就石沉大海

所以注入的固定节奏是：`ime set` 切过去 → 注入 → `ime set` 切回用户自己的输入法。
用完**务必切回**，否则用户手机上打字没有键盘 UI。

#### 手机 agent 的前缀缓存（2026-10-03 重做，附实测）

**问题**：`server.py` 每轮把易变块（工作记忆 / 长期记忆召回 / 未完成任务 / loop 提示）
拼在 `msgs[1:]` **之前**，位置 1 就变 ⇒ 其后整段历史全部脱缓存，
表现为**命中数恒定在 ~9.9k 不随历史增长**，会话越长命中率越低（实测 93.9% → 80.2% → 65.8%）。

**修法**（`server.py` 的 `agent_stream`，见 `D:\Godot4.7_Proj\...` 之外的本地镜像）：
1. 易变块用 `_wire_pin()` **只追加地 append 进 `msgs`**，请求统一为 `[_sys] + msgs[1:]`。
   关键：只把易变块挂在请求末尾是**不够的**——下一轮会在同一位置分叉，
   把「上一条 assistant 回答」一起挤出缓存。必须真正写回历史。
2. 长期记忆块用 `_wire_pin_lines()` **按行分别去重**，只有新召回的事实才进历史（压住膨胀）。
3. 缩小单轮尾部：`MEM_STATE_DONE_N=3` / `MEM_STATE_DONE_CHARS=40`（原本 `done[-8:]` 全量、
   单条上百字），`MEM_AUTO_CHARS` 默认 900 → 400。**这三个都能用同名环境变量调回去。**
4. `call_model` 里加了 `[cache] 命中 x/y = z%` 日志（写进 `~/agent/boot.log`），
   `index.html` 的用量行也加了 `🎯缓存 hit/prompt (rate%)`——**修之前你根本没有可信口径**。

**实测（同一组提示词，deepseek-v4-flash，thinking=high）**：

| 场景 | 原始版 | 修好后 |
|---|---|---|
| 自由长文（每次回答 1500+ 字，最坏情况） | 93.9 / 80.2 / **65.8%** | 94.7 / 80.0 / 83.2%（累计 85.2%） |
| 真实工具用法（每轮 2~3 次工具往返） | 89.1 / **72.7%** | 93 / 98.7 / 95.3 / 98.8%（**累计 95.8%**） |

> **分辨口径**：前缀缓存的单轮命中率上限 ≈ 1 − (上一条回答 + 新提问 + 新钉入块) / 总 prompt。
> 所以「长文问答」天然到不了 95%（每轮 2000 token 全新正文）；**真实 agent 用法（多轮工具往返、
> 回答短）才是稳态场景，第 2 轮起稳定 97~99%**。别拿长文测试否定优化。

#### S2 去全局化（已完成，2026-10-03）

把 5 个模块级可变全局（`SESSIONS` / `MEM_CACHE` / `RUN_STATE` / `_PLAN` / `read_cache._cache`）

**手法**（关键，别改回去）：用 `SessionBound` **会话绑定代理**，把 `_PLAN` / `RUN_STATE`

### 硬性坑（每个技能都适用）

1. **`--log-file` 必须给**。受限沙箱里 Godot 写不了 `user://` 会直接崩，且日志要写到工程内可写路径。
2. **数行必须用 LF 字节数**（`[System.IO.File]::ReadAllText($f) -split "`n"` 的 count-1）。
   `Get-Content` 在中文 UTF-8 文件上会**少数约 6%**，历史上把 Main.gd 数成 911 行。
3. **改完必须跑测试**，退出码 `0`=全绿 / `1`=有失败。上一轮的「全绿」不构成本轮依据。
4. **不要手动编辑 `.godot\`**（引擎缓存）。
5. **带格式的 docx 段落不要用 `paragraph.text = …` 覆盖**（会丢格式），用 `OxmlElement` 造同构 `<w:p>`。
6. 端口 **8000 / 9500 一次只能被一个 Godot 编辑器占用**；同时开两个项目，后开的连不上。
7. 「无 `class_name` 的模块」引用方**必须 preload 成常量**（裸写名字会解析失败）。
8. 写 PowerShell 时注意（**2026-10-02 实测的三个真坑**）：
   - **本机没有 `pwsh`**（PATH 里没有 PowerShell 7）。工具 shell 是 **Windows PowerShell 5.1**。
     调用脚本一律用 `& "<绝对路径>" -参数 值`，**不要写 `pwsh -File ...`**。
   - **`.ps1` 必须存成 UTF-8 带 BOM**。PS 5.1 读无 BOM 的 UTF-8 会按 ANSI(GBK) 解码，
     中文字符串会直接变成「字符串缺少终止符」这类**解析错误**。用 `write`/`edit` 工具改完要确认 BOM 还在。
   - **不要写 `Write-Host "..." -f $a, $b`**。PS 5.1 会把 `-f` 当成 `-ForegroundColor` 的缩写，
     报 `无法将值"31697500"转换为类型 System.ConsoleColor`。要写成 `Write-Host ("..." -f $a, $b)`。
9. Python 输出坑：本机 Python 的 stdout 默认走系统 ANSI 代码页（**GBK**），
   `print` 非 GBK 字符（如 `⚠`）会 **UnicodeEncodeError 崩溃**。
   技能脚本已统一 `sys.stdout.reconfigure(encoding="utf-8", errors="replace")`。
   另外 **pwsh 的 `>` 重定向会写成 UTF-16LE**（带 `FF FE` BOM），别用它抓中文日志；
   需要精确文本时让 Python 直接写 UTF-8 文件，或用 base64 中转。
10. `Get-ChildItem env:` 会因环境表有重名键而**抛异常**，别用它枚举环境变量。
