# 鸿蒙（HarmonyOS / OpenHarmony）导出验证 —— 2026-10-06 · 第七十五版

**一句话**：Godot 官方**没有**鸿蒙导出，但社区有可行 port；本机已把
「Godot 4.5-beta → 鸿蒙 HAP → 自签 → 验签」整条链路**实际跑通并验收**。
**但产物从未上过真机**（没有鸿蒙 5+ 设备），所以本文**不含任何帧率结论**。

## 三、四个坑（按被咬的顺序，都卡过一次）

1. **`--script` 与 `--editor` 互斥**：`godot --headless --editor --script foo.gd` 里 `--script` **不会执行**
   （main.cpp 的分支决定），所以"EditorScript 自动化导出"这条路不通 ⇒ 必须写 **EditorPlugin**。
2. **`EditorExport` / `EditorSettings` / `EditorInterface` 都不是 GDScript 全局类**：
   `EditorExport.get_singleton()` 直接 Parse Error，`Engine.get_singleton("EditorExport")` 也是 null
   —— `EditorExport` **没注册进 ClassDB**（只有 `EditorExportPlatform` / `EditorExportPreset` 注册了）。
   正解：`ClassDB.instantiate("EditorExportPlatformOpenHarmony")` 自己 new 平台；
   编辑器设置走 `EditorInterface.get_editor_settings()`；`preset.name/export_path` 也不能点号赋值（用 `set()/get()`）。
3. **新建预设的 `files` 为空**，`update_files()` 没绑给脚本 ⇒ 直接 `export_project()` 报
   `Must select at least one file to export.`（来自 `save_pack` 的 `p_total < 1`）。
   正解：**别自己调 `export_project()`，走官方 CLI `--export-debug`**，它会自己处理文件清单。
4. **`--export-debug` 的两项必备设置**：工程里 `textures/vram_compression/import_etc2_astc=true`
   （否则 "ETC2/ASTC texture compression must be enabled for OpenHarmony export"），
   预设里 `build/override_project_dir=true`（否则第二次导出报 "Project dir is already exists"）。

**插件内置签名**：`build/sign=true` 时它把 `-profileFile` 原样交给 `hap-sign-tool`，
**必须给 `.p7b`**（给 `.pem` 报 `11012005 Not support file`）。
⇒ 本机做法是 `build/sign=false` 出未签名 HAP，再用 `deveco.ps1 sign` 签（那条链已在第七十四版验证）。

## 四、这套 port 与"帧率"的关系（只登记事实，不下结论）

- **它没有"请求高刷"的接口**：只有 `ohos_wrapper_get_display_refresh_rate()`
  （`OH_NativeDisplayManager_GetDefaultDisplayRefreshRate`，只**读**），没有 set/request。
- **鸿蒙侧默认没有 vsync 节流**（另一位移植者的记录：Vulkan `vkQueuePresentKHR` 不带来垂直同步时
  渲染线程会空转、GPU 发热，他用硬编码 `delay_usec(16000)` 锁 60 FPS）
  ⇒ 与 Android 侧"厂商按包名把应用钉在 60 Hz"是**两套完全不同的机制**。
- 引擎侧**怎么取帧率**：`DisplayServer.screen_get_refresh_rate()` 在 OpenHarmony 平台已实现
  （`DisplayServerOpenHarmony::screen_get_refresh_rate`）。

**⇒ 必须真机实测才知道**：鸿蒙设备给多少 Hz、锁不锁 60、能不能要到高刷。
在没有真机之前，**本文不写任何帧率数字**。

## 五、下一步（等有鸿蒙 5+ 设备时按顺序做）

1. **装机**：`deveco.ps1 install -Hap <签名.hap>` 之前，先把设备 udid 写进 profile
   （`deveco.ps1 sign -Udid <udid>`）—— debug profile 是**按设备 udid 钉死**的，不然装不上。
2. **取第一组数据**：跑最小验证包，看 hilog 里 `OHOS-VERIFY` 那两行
   （`_ready` 打 OS/版本，`_process` 每 2 秒打 `fps` 与 `screen_get_refresh_rate()`）；
   再配合 `hdc shell hidumper -s RenderService -a screen` 看设备侧刷新率。
3. **再谈迁《解域》**：我们工程是 **4.7.1**，port 是 **4.5-beta**，直接导入会有 API/语法差异。
   正确顺序是：先跑 `--import` 解析自检 → 列出报错 → 评估改动量 → 再决定迁不迁。
   **不要**拿 4.5-beta 编辑器直接开 4.7.1 工程当"验证"，那会把两个变量混在一起。
