# netcode-godot · 联机可行性与成本备忘

> **当前状态：不做联机。** 用户 2026-10-02 明确「先不做联机，但把最小可行方案 + 成本写清楚」。
> 本技能的用途是**让以后的决定有依据**，而不是催你去写联机代码。
> 本文件里 **没有一行联机实现**，也不该由本技能顺手写出来。

先读 `..\_shared\环境事实.md`。

---

## 一、先明确：这个决定为什么现在可以往后放

联机不是「加个库」的功能，而是**架构约束**。它一旦进来，会反向要求改这些**已经写好的**东西：

| 现在的做法（单机） | 联机要求 | 影响面 |
|---|---|---|
| 输入直接改本地状态（`_process` 里就地写） | 输入与模拟分离，模拟可被重放 | 几乎全部 gameplay 模块 |
| 玩家设备 = 唯一真相 | 需要一个权威来源 | 决策层 |
| `Enemy` 手写状态机 + 24 兵种协同 | 每个单位的决策要可同步/可复现 | `entities/enemy/Enemy.gd` 及协同 |
| 载具在 `VehicleController` 里本地演算 | 车辆位置/朝向要同步（且高频） | `scenes/gameplay/VehicleController.gd` |
| 地形 `HeightGrid` / `MapGenerator` 本地生成 | 双方地形必须一致（或由权威下发） | `systems/terrain/` |

**结论**：越晚做，返工越多；但**现在做**会把垂直切片的迭代速度拖垮。
所以正确处置是：**记录结论 + 划清触发条件**，把决定权留在能看见全貌的时候。

## 二、选型（Godot 4.7.1 实测能力边界）

> 以下 API 事实来自本工程 `docs/kb/refs/godot-api`（Godot **4.7.1-stable** 生成）。
> **重要**：这套文档里**没有** `rollback` / `determinism` 相关页 ——
> 也就是说 **Godot 内置高层联机不提供「预测回滚」**，别指望开个开关就有。
> 需要回滚就得自己写（或交给 Netfox 那类库）。

| 方案 | 是什么 | 适合 | 代价 |
|---|---|---|---|
| **Godot 内置高层**（`ENetMultiplayerPeer` + `SceneMultiplayer` + `MultiplayerSynchronizer` / `MultiplayerSpawner`） | 引擎自带，`MultiplayerSynchronizer` 按属性同步（有 `replication_interval` / `delta_interval` 可调） | 小规模、状态量不大、host 权威 | 需要自己管权威与延迟补偿；`SceneReplicationConfig` 只支持可同步属性（**`Object`/`Resource` 类型属性不支持同步**，实例 ID / RID 也不行） |
| **Netfox**（已 clone 到 `D:\Godot4.7_Proj\_addon_staging\netfox`，v1.49.4） | 纯 GDScript 的一套 addon：时序一致、客户端预测、服务器调和、插值 | 需要「手感不飘」的动作向联机 | 引入一套自己的 tick/回滚约定，**要求把游戏逻辑改造成可重放**；自带 `vest` 单测库需剔除 |
| **RPC 自研**（`rpc` / `rpc_id` 手写） | 最朴素 | 回合制 / 低频状态（如战术地图、结算） | 同步谁的权威、丢包怎么办都要自己写 |

**`SceneMultiplayer` 的两个实测细节**（会直接影响架构）：

- **导出到 Android 必须开 `INTERNET` 权限**（引擎文档明确写了），否则任何网络通信被系统拦掉。
  → 与 `release-engineering-android` 的隐私清单联动：**开权限 = 必须改隐私声明**。
- 高层协议是**实现细节**，官方明确「非 Godot 服务器不要依赖它」——
  **想自己写后端（例如独立服务器）就要考虑这条**。

## 三、最小可行方案（MVP）—— 三个阶梯，别跳级

### 阶梯 1：**同屏 / 热座协作**（零网络，1~2 天）
不做任何网络，先把「多个可操作单位 + 指挥权切换」在本地做扎实。
产出：验证 gameplay 在「多个被控单位」下不乱 → 这是后面所有联机形态的前提。

### 阶梯 2：**Host 权威 + 状态同步**（推荐的第一版真联机，4~8 周量级）

```
一台设备当服务器（host），另一台连进来
host 跑完整模拟 → 按固定频率下发「世界状态快照」
client 只发送「输入意图」，收到快照后插值表现
不做预测回滚：client 自己的单位也等服务端确认（有延迟，但实现简单、不会漂移）
```

- 用 `ENetMultiplayerPeer` 建连，`MultiplayerSynchronizer` 同步单位的位置/朝向/血量。
- **必须先把 tick 固定下来**：`_process(delta)` 换成**固定步长**（例如 20~30 Hz）累加器，
  否则两端模拟速度不同，同步再准也会漂。
- 载具这类高频对象：降低同步频率 + 只同步「位置/朝向/炮塔角」，其余本地插值。
- 适合：**COOP PvE（合作打 AI）**。也正好匹配现在的 AI 驱动玩法。

### 阶梯 3：**预测 + 回滚**（真 PVP 才需要；不便宜）

- 需要「输入与模拟分离」+「可重放」+「确定性」。
- **Godot 的浮点物理不保证跨设备位级一致**，所以要真确定性通常得上定点数 —— 那是重写级改造。
- 现实中更常见的折中：**服务端权威 + 客户端预测 + 服务器调和**（Netfox 的那套），
  **不需要位级确定性**，但要求逻辑能「按输入重算」。
- 触发条件（见第六节）：只有当**对抗性 PVP 是核心卖点**时才值得。

## 四、如果要做，改造点清单（按依赖顺序）

不评估、不排序就先动手，一定会返工。**这个顺序不能反**：

1. **固定 tick**：把 `_process(delta)` 的自由步长改成固定步长累加器（先单机做，能测）。
2. **输入/模拟分离**：输入只产生「意图」，模拟只消费意图（单机可测：录制意图回放应得同样结果）。
3. **权威归属**：明确每个对象的 `multiplayer_authority`（谁是真相）。
4. **可同步状态裁剪**：只同步「表现必需」的属性；把 `Resource`/实例 ID 这类**不可同步**的东西从同步集里拿掉。
5. **地图一致性**：地形改由权威下发种子/高度图，而不是各自本地生成。
6. **AI 决策同步**：至少保证「敌人位置/状态」同步；决策若在两端各跑，必须同种子。
7. **掉线/重连/超时**：`SceneMultiplayer.auth_timeout` 默认 3 秒，需要按玩法调。
8. **作弊与信任边界**：host 权威 = 房主能作弊（COOP 可接受，竞技不可接受）。

## 五、成本与风险（诚实版）

| 项 | 代价 | 说明 |
|---|---|---|
| 固定 tick 改造 | 中 | 会动到所有 `_process` 依赖的模块，需要一轮回归 |
| 输入/模拟分离 | **高** | 触及 gameplay 主干；`Main.gd`（398 行）与其子模块都要过一遍 |
| 预测回滚 | **很高** | 本质是重做模拟层；不建议在没有验证过阶梯 2 之前碰 |
| 联机专用服务器 | 高（**持续成本**） | 要么买服务器，要么走 host 权威（房主当服务器） |
| 测试与调优 | 高 | 延迟/丢包/时钟漂移都要可复现地测 —— 需要一套「模拟弱网」的测试基建 |
| 合规 | 中 | Android `INTERNET` 权限、隐私声明、数据安全表单都要跟着改 |

**风险提示**：
- 24 兵种 + 载具协同是**同步量最大**的部分；先把单位数压下来验证，别一上来就全量。
- 现在的 AI 是手写状态机。如果以后换成行为树（Beehave/LimboAI），
  **先做行为树、再做联机**——否则两件事同时返工。

## 六、触发条件：什么时候该重新拿这个决定出来谈

满足**任意一条**就值得重新评估（否则保持不做）：

- [ ] 单机垂直切片的核心循环已经**稳定且好玩**（不是「能跑」，是「想再玩一局」）。
- [ ] 玩家反馈里**主动提到**「想和朋友一起玩」。
- [ ] 单机的 AI 已经能满足对抗需求（那 PVP 的边际价值就低，可以不做）。
- [ ] 出现**明确的发行/商业要求**（例如平台方或发行方明确要联机）。
- [ ] 团队有**能专职做联机**的人力（联机是持续性投入，不是一次性）。

**在这些条件出现之前，不要为了「以后可能要做」而提前抽象模拟层** ——
那会拖慢现在唯一重要的事：把切片做扎实。

## 七、铁律

1. **本技能不写联机代码。** 决定变了要先重新评估，再单独开一轮。
2. **不要声称 Godot 内置联机有预测回滚** —— 4.7.1 的 API 里没有这东西（详见 `docs/kb/refs/godot-api`）。
3. **不要跳级**：阶梯 2 没验证过就不要碰阶梯 3。
4. **先固定 tick，再谈同步**；反过来做一定返工。
5. 评估结论要**写进进度文件与 docx**（第十九章待确认决策清单 / 七、已知待拍板），
   不要只留在会话里。
6. 涉及 Android 联网 = **`INTERNET` 权限 + 隐私声明同步更新**，两手一起做。
